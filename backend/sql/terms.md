
## PostgreSQL

PostgreSQL - это объектно-реляционная СУБД. Она предоставляет инструменты (набор встроенных возможностей и команд) для создания и управления базами данных, поддерживает SQL, позволяет работать со сложными структурами (включая JSON/JSONB, массивы, пользовательские типы данных) и обеспечивает транзакции с соблюдением принципов ACID. 

PostgreSQL - это СУБД со встроенным собственным движком хранения, а не просто набор движков на выбор.

Сервер PostgreSQL - это процесс, который крутится на компьютере (на Windows виден в службах вроде `postgresql-x64-xx`). Он не имеет своего "окна" с интерфейсом. Его лицо - это клиенты вроде pgAdmin.

Инструменты PostgreSQL:

1. Базовые SQL-команды (create, alter, drop);
2. Сложные структуры (JSON, JSONB, Массивы, пользовательские типы данных)
3. Надёжность. Команды управления транзакциями, уровни изоляции, механизмы внутри СУБД (за соблюдение ACID отвечают журнал предзаписи WAL для долговечности (durability) и механизм MVCC (Multiversion Concurrency Control) для изоляции).

У PostgreSQL монолитная архитектура, присутствуют:

- Единый механизм хранения (условно, движок), который сразу даёт транзакции, MVCC, WAL и т.п.
- Есть различные методы доступа: B-Tree, GiST, GIN, BRIN - типы индексов, выбираемые под задачу
- Есть табличные методы и расширения (подключение внешних обёрток для данных из других систем - Foreign Data Wrappers), но базовая структура остаётся одной и той же.

## pgAdmin

pgAdmin - графический интерфейс (GUI) для работы с PostgreSQL. Оне не является СУБД сам по себе, с его помощью удобно подключаться к серверу PostgreSQL, визуально управлять объектами (таблицами, индексами, триггерами), писать и выполнять SQL-запросы, мониторить состояние базы и анализировать производительность. Это программа-посредник, отображающая то, что отдаёт сервер.

## psql

psql - это консольный клиент для PostgreSQL: программа, которая запускается в терминале/командной строке и позволяет писать SQL-запросы без графических окон.

## Схемы (Schemas)

Схемы в PostgreSQL - это логические контейнеры (папки) внутри базы данных, который группирует объекты: таблицы, представления, индексы, функции и т.д. Это своего рода "папка" для таблиц.

Аналогия:

- База данных - диск `C:`
- Схема - папка внутри диска `C:\Projects\MyApp`
- Таблица - это файл внутри папки `users.csv`

Схемы нужны:

- **Изоляция объектов**. В одной БД можно создать две таблицы с одинаковым именем, если они в разных схемах `public.users` и `archive.users`.
- **Управление правами доступа**. Можно дать разным пользователям доступ к разным схемам.
- **Логическая организация.** Удобно разделять объекты по проектам, модулям, типам данных.

Схема по умолчанию - `public`, в неё попадают объекты, если явно не указать другую.

- Движок - сменный модуль внутри СУБД, отвечающий за хранение и чтение с диска.
